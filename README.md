# 바이브코딩 vs 프로세스 기반 개발 비교 프로젝트

AI(바이브코딩)로만 개발한 결과물과 소프트웨어 공학 프로세스를 거쳐 개발한 결과물을 비교하는 팀 프로젝트입니다.  
동일한 주제(쇼핑몰)를 두 가지 방식으로 구현하여 산출물의 품질과 과정의 차이를 분석합니다.

---

## 브랜치 구조

| 브랜치 | 설명 |
|--------|------|
| `main` | 공통 문서 허브 — 회의록(`docs/`)과 설계 산출물(`process_output/`)을 관리합니다 |
| `vibe_coding` | **바이브코딩 구현체** — AI와의 대화만으로 개발한 쇼핑몰 소스코드(`vibe_coding_output/`)가 있습니다 |
| `1-feat-프로세스-기반-sw` | **프로세스 기반 구현체** — 요구사항 분석 → 설계 → 구현 순서를 따른 Spring Boot 쇼핑몰과 Mermaid 설계 소스(`design/`)가 있습니다 |

---

## 디렉터리 구조 (main 브랜치 기준)

```
.
├── docs/                        # 회의록 (단계별 팀 회의 기록)
│   ├── 주제선정/                #   주제 후보 검토 및 선정 회의
│   ├── 계획/                   #   프로젝트 계획 및 일정 회의
│   └── 요구사항분석/            #   요구사항 분석 회의
│
└── process_output/              # 설계 산출물 (프로세스 기반 개발 결과물)
    ├── 요구사항명세서.md/.docx
    ├── 유스케이스명세서.md/.docx
    ├── 테스트계획서.md/.docx
    ├── ERD.png
    ├── 클래스다이어그램.png
    ├── 유스케이스다이어그램.png
    ├── 상태다이어그램.png
    └── 시퀀스다이어그램/
```

> `vibe_coding` 브랜치에는 위 공통 문서 외에 `vibe_coding_output/`(구현 소스)가 추가됩니다.  
> `1-feat-프로세스-기반-sw` 브랜치에는 `design/`(Mermaid 소스 파일)과 Spring Boot 프로젝트가 추가됩니다.
