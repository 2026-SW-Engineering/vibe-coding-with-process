# 쇼핑몰 주문 시스템 — 소프트웨어 요구사항 명세서

## 1. 개요

본 문서는 쇼핑몰 주문 시스템의 기능 및 비기능 요구사항을 정의한다. 본 시스템은 SW 공학 프로세스(요구사항 분석 → 설계 → 구현 → 테스트)를 적용한 개발과 바이브코딩 방식 개발의 차이를 비교하기 위한 과제의 대상 시스템이다. 요구사항 분석과 유스케이스 모델링을 거치며 상태 흐름·액터 책임·용어 정의가 정교화되었고, 그 결과를 본 문서에 반영하였다.

## 2. 용어 정의

| **용어** | **정의** |
| --- | --- |
| 비회원 | 회원가입을 하지 않은(계정이 없는) 사용자. 상품 조회와 회원가입만 가능하다. |
| 회원 | 회원가입을 완료한 일반 사용자 역할의 계정 보유자. |
| 관리자 | 관리자 역할(role)을 가진 계정. 회원가입으로 생성되지 않으며 시드 데이터로만 존재한다. |
| 확정 가격 | 주문 생성(확정) 시점에 고정된 항목별 가격. 이후 상품 가격이 변경되어도 변하지 않는다. |
| 시드 데이터 | 시스템 초기에 적재되는 데이터(상품 목록, 관리자 계정 등). |

## 3. 액터 정의

| **액터** | **주요 책임** |
| --- | --- |
| 비회원 | 회원가입, 상품 조회 |
| 회원 | 로그인/로그아웃, 상품 조회, 장바구니 관리, 주문 생성, 주문 조회, 주문 전체 취소, 부분 환불 요청 |
| 관리자 | 로그인/로그아웃, 상품 가격 변경, 상품 출고, 환불 승인/거부, 전체 주문 조회 |
| 결제 시스템 (외부) | 결제 승인/실패 처리. 외부 PG 연동 없이 모의(mock) 처리한다. |
| 배송 시스템 (외부) | 배송 진행 상태를 시스템에 통지한다. 모의(mock) 데이터로 동작한다. |

## 4. 기능 요구사항

### 4.1 회원 / 인증

- 사용자는 이메일과 비밀번호로 회원가입할 수 있다. 이메일은 시스템 내에서 유일해야 한다.

- 회원가입으로 생성되는 계정은 항상 일반 사용자 역할이며, 관리자 계정은 시드 데이터로만 존재한다.

- 회원과 관리자는 이메일과 비밀번호로 로그인하고, 로그아웃할 수 있다.

- 비회원은 상품 조회와 회원가입만 가능하며, 장바구니·주문·환불 기능은 사용할 수 없다.

- 관리자 전용 기능에 일반 사용자가 접근을 시도하면 시스템은 권한 거부로 응답한다.

### 4.2 상품 조회

- 모든 사용자(비회원 포함)는 등록된 상품을 조회할 수 있다.

- 조회 시 표시 항목은 상품명과 가격이다. (재고 잔여 여부는 표시하지 않는다.)

- 상품 데이터는 시드 데이터로 초기 적재된다.

- 일반 사용자는 상품을 등록하거나 삭제할 수 없다.

### 4.3 장바구니

- 로그인한 회원은 상품을 수량과 함께 장바구니에 담을 수 있다.

- 회원은 장바구니에 담긴 항목의 수량을 변경하거나 항목을 삭제할 수 있다.

- 상품 가격이 변경되면 장바구니에 표시되는 가격도 현재 가격으로 반영된다.

- 결제는 장바구니에 표시된 현재 가격으로 진행된다.

- 장바구니에 담을 당시 재고가 있던 상품이 결제 시점에 품절된 경우, 시스템은 해당 항목을 결제에서 제외하고 회원에게 알린다.

### 4.4 주문 / 결제

- 로그인한 회원은 장바구니의 일부 또는 전체 항목을 선택하여 주문을 생성할 수 있다.

- 주문 생성 시 시스템은 각 항목의 현재 가격을 확정 가격으로 고정하고, 재고를 주문 수량만큼 차감한다.

- 재고 차감과 주문 생성은 원자적으로 처리되어야 한다. (상세 동시성 보장은 비기능 요구사항 참조)

- 결제는 외부 PG 연동 없이 모의(mock) 처리하며, 성공 또는 실패를 사용자가 선택하거나 시스템이 시뮬레이션할 수 있다.

- 결제 성공 시 주문은 결제완료 상태가 되고, 결제 실패 시 차감된 재고는 자동 복원되며 주문은 취소완료 상태로 기록된다.

- 주문 총액은 각 항목의 (확정 가격 × 수량) 합계와 일치해야 한다.

### 4.5 주문 조회

- 회원은 자신의 주문 내역 목록과 개별 주문의 상세 정보(주문 항목, 수량, 항목별 확정 가격, 총액, 현재 상태)를 조회할 수 있다.

- 회원은 다른 사용자의 주문을 조회할 수 없다.

- 관리자는 전체 사용자의 주문 목록 및 상세 정보를 조회할 수 있다.

### 4.6 취소 / 환불

- 회원은 결제완료 또는 배송준비 상태의 주문에 대해 전체 취소를 요청할 수 있다. 전체 취소 시 모든 항목의 재고가 복원되고 주문 상태는 취소완료로 변경되며, 관리자 승인 없이 즉시 처리된다.

- 회원은 배송완료 상태의 주문에 대해 부분 환불을 요청할 수 있으며, 환불 대상 항목과 수량을 지정한다. 부분 환불은 즉시 처리되지 않고 관리자 승인을 대기하는 환불요청 상태가 된다.

- 관리자가 부분 환불을 승인하면 환불 수량만큼 재고가 복원되고, 환불 금액은 (해당 항목의 확정 가격 × 환불 수량)으로 계산되며, 주문 상태는 부분환불로 변경된다.

- 관리자가 부분 환불을 거부하면 재고와 주문 금액은 변경되지 않고 주문 상태는 배송완료로 복귀한다.

- 이미 부분환불 상태인 주문에 대한 추가 환불은 불가능하다.

- 배송중 상태에서는 취소도 환불도 불가능하다.

- 부분 환불 가능 기한은 배송완료 후 7일 이내로 한다.

### 4.7 관리자 기능

- 관리자는 등록된 상품의 가격을 변경할 수 있다. 변경된 가격은 이후 시점부터 적용되며, 이미 확정된 주문의 항목 가격에는 영향을 주지 않는다.

- 관리자는 결제완료 상태의 주문에 대해 상품 출고를 수행하여 주문을 배송준비 상태로 전이시킨다. (출고는 본 시스템의 마지막 책임이며, 이후 배송 상태는 배송 시스템이 통지한다.)

- 관리자는 환불요청 상태의 부분 환불 요청을 조회하고 승인 또는 거부할 수 있다.

## 5. 주문 상태 및 전이 규칙

주문 상태: 결제대기, 결제완료, 배송준비, 배송중, 배송완료, 취소완료, 환불요청, 부분환불

### 5.1 상태 전이

| **상태 전이** | **조건 / 행위** | **트리거** |
| --- | --- | --- |
| 결제대기 → 결제완료 | 결제 성공 (주문 생성) | 시스템(결제 결과) |
| 결제대기 → 취소완료 | 결제 실패 시 재고 복원 후 기록 | 시스템(결제 결과) |
| 결제완료 → 배송준비 | 상품 출고 | 관리자 |
| 배송준비 → 배송중 | 배송 진행 통지 | 배송 시스템(외부) |
| 배송중 → 배송완료 | 배송 완료 통지 | 배송 시스템(외부) |
| 결제완료 → 취소완료 | 전체 취소 (재고 복원) | 회원 |
| 배송준비 → 취소완료 | 전체 취소 (재고 복원) | 회원 |
| 배송완료 → 환불요청 | 부분 환불 요청 (7일 이내) | 회원 |
| 환불요청 → 부분환불 | 환불 승인 (수량만큼 재고 복원) | 관리자 |
| 환불요청 → 배송완료 | 환불 거부 (변경 없음) | 관리자 |

### 5.2 전이 규칙

- 정상 배송 흐름(결제대기 → 결제완료 → 배송준비 → 배송중 → 배송완료)은 역행할 수 없다.

- 배송중 상태에서는 전체 취소와 부분 환불이 모두 불가능하다.

- 전체 취소는 결제완료·배송준비 상태에서만 가능하다.

- 부분 환불은 배송완료 상태에서만, 배송완료 후 7일 이내에만 가능하다.

- 이미 부분환불된 주문은 추가 환불이 불가능하다.

## 6. 비기능 요구사항

### 6.1 데이터 정합성

- 어떤 시점에도 상품의 재고 수량은 0 이상이어야 한다.

- 취소완료 상태의 주문은 결제 금액이 0이다.

- 부분환불 상태의 주문은 [주문 결제 금액 = Σ(항목 확정 가격 × 항목 수량) − Σ(환불 금액)]을 만족해야 한다.

- 주문에 기록된 항목별 가격은 주문 확정 시점의 가격으로 고정되며, 이후 상품 가격이 변경되어도 해당 주문의 항목 가격은 변하지 않는다.

### 6.2 동시성

- 동일 상품에 대한 동시 주문 요청에서 재고 초과 판매(oversell)가 발생해서는 안 된다. 잔여 재고 한도 내에서만 주문이 성공하고 초과분은 실패 처리되어야 한다. (예: 재고 1개에 두 명이 동시 주문 시 정확히 1명만 성공)

- 구체적 동시성 제어 방식(비관적/낙관적 락, 트랜잭션 격리 수준 등)은 설계 단계에서 결정한다.

### 6.3 신뢰성 / 복구

- 재고 차감·결제·재고 복원이 포함된 처리(주문 생성, 전체 취소, 환불 승인 등)는 원자적으로 수행되어야 하며, 중간 실패 시 부분 적용된 상태로 남지 않고 롤백되어야 한다.

- 결제 실패·취소·환불 이후에도 재고 수량과 주문 상태는 항상 정합성을 유지해야 한다.

### 6.4 보안 및 권한

- 비밀번호는 평문으로 저장하지 않고 해시하여 저장한다.

- 일반 사용자는 본인 데이터에만 접근할 수 있다.

- 관리자 전용 기능(API)은 관리자만 호출할 수 있어야 한다.

- (추후 보안 요구사항을 추가할 수 있다.)

### 6.5 성능

- 단순 조회 요청(상품 목록 조회, 장바구니 조회 등)은 약 2초 이내에 응답한다.

- 재고 차감·결제가 포함된 요청(주문 생성 등)은 약 5초 이내에 응답한다.

## 7. 범위 및 제약사항

- 결제는 외부 PG 연동 없이 모의(mock)로 처리한다. 결제 성공/실패는 사용자가 선택하거나 시스템이 시뮬레이션한다.

- 배송 상태 전이(배송준비 이후)는 외부 배송 시스템이 통지하는 것으로 가정하며, 모의(mock) 데이터로 동작한다.

- 상품 목록과 관리자 계정은 시드 데이터로 적재한다.

- 향후 실제 PG 연동 시 비동기 결제 흐름(리다이렉트·웹훅), 재고 임시 예약, 결제 검증, 웹훅 멱등성, 환불 API 정합성 등이 추가로 고려되어야 한다. 본 과제 범위에서는 제외한다.
