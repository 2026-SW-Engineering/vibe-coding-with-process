# **쇼핑몰 주문 시스템 — 유스케이스 명세**

액터

- 비회원: 회원가입하지 않은(계정이 없는) 사용자. 

- 회원: 회원가입을 완료한 계정 보유자. 

- 관리자: 시드 데이터로만 존재하는 관리자 역할 계정.

## **UC-01. 회원가입**

| **시스템 제목** | 쇼핑몰 주문 시스템 |
| --- | --- |
| **유스케이스 이름** | 회원가입 |
| **액터** | 비회원 |
| **시작조건** | 로그인되어 있지 않다(계정이 없는 사용자다). |
| **기본 흐름** | 1. 비회원이 이메일과 비밀번호를 입력하고 회원가입을 요청한다. 2. 시스템은 입력한 이메일이 시스템 내에서 유일한지 검증한다. 3. 시스템은 일반 사용자 역할(role)로 계정을 생성한다. 4. 시스템은 회원가입 완료를 사용자에게 알린다. |
| **대안 흐름** | 2A. 이메일이 이미 존재하는 경우: 시스템은 중복을 알리고 가입을 중단한다. 1A. 이메일 형식이나 비밀번호가 유효하지 않은 경우: 시스템은 오류를 알리고 재입력을 요구한다. |
| **종료 조건** | 새 계정이 일반 사용자 역할로 생성된다. (관리자 계정은 회원가입으로 생성되지 않으며 시드 데이터로만 존재한다.) |

## **UC-02. 로그인 / 로그아웃**

| **시스템 제목** | 쇼핑몰 주문 시스템 |
| --- | --- |
| **유스케이스 이름** | 로그인 / 로그아웃 |
| **액터** | 회원, 관리자 |
| **시작조건** | (로그인) 가입된 계정이 존재한다. (로그아웃) 로그인되어 있다. |
| **기본 흐름** | 1. (로그인) 사용자가 이메일과 비밀번호를 입력한다. 2. 시스템은 자격 증명을 검증하고 인증 세션을 시작한다. 3. 시스템은 사용자의 역할(일반 사용자 또는 관리자)에 따른 화면을 제공한다. 4. (로그아웃) 로그인된 사용자가 로그아웃을 요청하면 시스템은 세션을 종료한다. |
| **대안 흐름** | 2A. 자격 증명이 일치하지 않는 경우: 시스템은 로그인 실패를 알리고 세션을 시작하지 않는다. |
| **종료 조건** | (로그인) 인증 세션이 시작되고 역할에 맞는 기능에 접근할 수 있다. (로그아웃) 세션이 종료된다. |

| **대안 흐름** | (없음) |
| **종료 조건** | 회원의 장바구니에 선택한 항목과 수량이 반영되어 있으며, 표시 가격은 항상 현재 가격이다. |

## **UC-05. 주문 생성**

| **시스템 제목** | 쇼핑몰 주문 시스템 |
| --- | --- |
| **유스케이스 이름** | 주문 생성 |
| **액터** | 회원, 결제 시스템(외부) |
| **시작조건** | 회원이 로그인되어 있고, 장바구니에 1개 이상의 항목이 담겨 있다. |
| **기본 흐름** | 1. 회원이 장바구니에서 주문할 항목(일부 또는 전체)을 선택한다. 2. 시스템은 선택한 각 항목의 현재 가격을 확정 가격으로 고정한다. 3. 시스템은 각 항목의 재고를 주문 수량만큼 원자적으로 차감한다. (동시 주문 시 재고 한도 내에서만 성공) 4. 시스템은 주문을 결제대기 상태로 생성한다. 5. 시스템은 결제 처리를 수행한다. (※ 결제 유스케이스 include) 6. 결제가 성공하면 주문 상태를 결제완료로 전이시킨다. 7. 시스템은 주문 번호와 총액을 회원에게 표시한다. |
| **대안 흐름** | 3A. 일부 항목이 품절된 경우: 담을 당시 재고가 있었으나 현재 품절된 항목은 결제에서 제외하고, 회원에게 알린 뒤 남은 항목으로 4단계부터 계속한다. 남은 항목이 없으면 주문 생성을 중단한다. 3B. 동시 주문으로 재고가 부족한 경우: 잔여 재고 한도 내에서만 주문이 성공하고 초과분은 실패 처리한다. 실패한 회원에게 재고 부족을 알린다. (예: 재고 1개에 두 명 동시 주문 시 정확히 1명만 성공) 5A. 결제 실패: 3단계에서 차감한 재고를 모두 원복하고, 주문 상태를 취소완료로 기록한 뒤, 회원에게 결제 실패를 알린다. |
| **종료 조건** | (성공) 선택 항목의 재고가 주문 수량만큼 차감되고, 주문이 결제완료 상태로 생성된다. 주문 총액 = Σ(항목별 확정 가격 × 수량)이 기록되며, 확정 가격은 주문 시점 가격으로 고정되어 이후 가격 변경에 영향받지 않는다. (실패) 차감했던 재고가 모두 원복되고, 주문이 취소완료 상태로 기록된다. |

| **시스템 제목** | 쇼핑몰 주문 시스템 |
| --- | --- |
| **유스케이스 이름** | 결제 |
| **액터** | 회원, 결제 시스템(외부) |
| **시작조건** | 주문이 결제대기 상태로 생성되어 있다. (주문 생성 유스케이스에 의해 include로 호출된다.) |
| **기본 흐름** | 1. 시스템은 결제 시스템(외부)에 결제 승인을 요청한다. 2. 결제 시스템은 결제 성공 또는 실패를 반환한다. (외부 PG(Payment Gateway, 결제대행사) 연동 없이 모의(mock) 처리하며, 결과를 사용자가 선택하거나 시스템이 시뮬레이션할 수 있다.) 3. 시스템은 결제 결과를 주문 생성 흐름에 반환한다. |
| **대안 흐름** | 2A. 결제 실패: 실패 결과를 반환하여 주문 생성 흐름이 재고를 원복하고 주문을 취소완료로 기록하도록 한다. |
| **종료 조건** | 결제 성공 또는 실패 결과가 주문 생성 흐름에 전달된다. (재고 차감/복원 및 주문 상태 전이는 주문 생성 유스케이스가 책임진다.) |

| **유스케이스 이름** | 주문 전체 취소 |
| **액터** | 회원 |
| **시작조건** | 회원이 로그인되어 있고, 주문이 결제완료 또는 배송준비 상태다. |
| **기본 흐름** | 1. 회원이 대상 주문에 대해 전체 취소를 요청한다. 2. 시스템은 주문에 포함된 모든 항목의 재고를 복원한다. 3. 시스템은 주문 상태를 취소완료로 변경한다. (관리자 승인 없이 즉시 처리) 4. 시스템은 취소 완료를 회원에게 알린다. |
| **대안 흐름** | 1A. 주문이 배송중 상태인 경우: 취소가 불가능하므로 시스템은 요청을 거부한다. 1B. 주문이 배송완료 상태인 경우: 전체 취소가 아닌 부분 환불 요청 대상이므로 시스템은 전체 취소를 거부한다. |
| **종료 조건** | 주문의 모든 항목 재고가 복원되고, 주문 상태가 취소완료로 변경된다. |

## **UC-09. 부분 환불 요청**

| **시스템 제목** | 쇼핑몰 주문 시스템 |
| --- | --- |
| **유스케이스 이름** | 부분 환불 요청 |
| **액터** | 회원 |
| **시작조건** | 회원이 로그인되어 있고, 주문이 배송완료 상태다. 배송완료 후 7일 이내다. 해당 주문이 이미 부분환불 상태가 아니다(재환불 불가). |
| **기본 흐름** | 1. 회원이 환불 대상 항목과 수량을 지정하여 부분 환불을 요청한다. 2. 시스템은 주문 상태를 환불요청으로 변경한다. 3. 시스템은 관리자 승인 대기 상태임을 회원에게 알린다. |
| **대안 흐름** | PRE(전제). 배송완료 후 7일이 지난 경우 또는 이미 부분환불된 주문인 경우: 시스템은 환불 요청을 거부한다. 1A. 주문이 배송중 상태인 경우: 환불이 불가능하므로 시스템은 요청을 거부한다. |
| **종료 조건** | 주문 상태가 환불요청으로 변경되고 관리자 승인을 대기한다. (재고/금액은 이 시점에 변경되지 않는다.) |

## **UC-10. 환불 승인 / 거부**

| **시스템 제목** | 쇼핑몰 주문 시스템 |
| --- | --- |
| **유스케이스 이름** | 환불 승인 / 거부 |
| **액터** | 관리자 |
| **시작조건** | 관리자가 로그인되어 있고, 환불요청 상태의 부분 환불 요청이 존재한다. |
| **기본 흐름** | 1. 관리자가 환불요청 상태의 요청을 조회한다. 2. (승인) 관리자가 승인하면 시스템은 환불 대상 항목의 수량만큼 재고를 복원한다. 3. 시스템은 환불 금액 = 해당 항목의 확정 가격 × 환불 수량으로 계산하고, 주문 상태를 부분환불로 변경한다. 4. (거부) 관리자가 거부하면 시스템은 재고와 주문 금액을 변경하지 않고, 주문 상태를 환불 요청 직전 상태(배송완료)로 복귀시킨다. |
| **대안 흐름** | (없음) |
| **종료 조건** | (승인) 환불 수량만큼 재고가 복원되고, 환불 금액이 계산되며, 주문 상태가 부분환불로 변경된다. (거부) 재고와 금액은 그대로이며, 주문 상태가 배송완료로 복귀한다. |

## **UC-13. 배송 상태 전이**

| **시스템 제목** | 쇼핑몰 주문 시스템 |
| --- | --- |
| **유스케이스 이름** | 배송 상태 전이 |
| **액터** | 배송 시스템(외부) |
| **시작조건** | 주문이 배송준비 상태다. |
| **기본 흐름** | 1. 배송 시스템(외부)이 배송 진행 상태를 우리 시스템에 통지한다. 2. 시스템은 통지에 따라 주문 상태를 배송준비 → 배송중 → 배송완료 순서로 전이시킨다. 3. (목 데이터로 배송 시스템이 상태를 변경하면 우리 시스템에 반영된다.) |
| **대안 흐름** | 2A. 역행 전이나 단계 건너뛰기 통지: 정상 상태 전이는 역행할 수 없으므로 시스템은 해당 전이를 허용하지 않는다. |
| **종료 조건** | 배송 시스템의 통지에 따라 주문 상태가 정상 순서로 전이된다(배송준비 → 배송중 → 배송완료). |
