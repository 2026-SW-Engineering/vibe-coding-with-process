## 요구사항 분석

- 주문 시스템
    - 고객이 상품을 검색 → 장바구니 → 주문 → 결제 → 환불
- Actor
    - Customer: 상품 검색, 장바구니 담기, 주문, 환불
    - Admin: 상품 등록, 재고 관리, 주문 처리
    - System: 결제 처리, 재고 차감, 상태 관리
- 기능 요구사항
    - 상품 관리
        - 상품 조회
        - 상품 등록/수정
        - 상품 재고 조회
    - 장바구니
        - 장바구니 상품 추가
        - 장바구니 상품 수량 변경
        - 장바구니 상품 제거
        - 장바구니 조회(목록&총액)
    - 주문
        - 주문 생성(장바구니 → 주문 전환)
        - 주문 조회(자신의 주문 이력)
        - 주문 상태 관리(대기 → 처리중 → 완료)
        - 주문 취소(특정 상태에서만 가능)
    - 결제 & 환불
        - 결제 처리(가격 확정 & 결제)
        - 전체 환불(주문 전체 취소)
        - 부분 환불(일부 상품 환불)
        - 환불 이력 조회
- 고려해야할 점
    - 재고 동시성 문제
    - 가격 변동 문제
    - 부분 환불 문제
    - 배송 상태에 따른 환불 불가 처리
    - 결제 실패 처리
    - 동일 상품 중복 장바구니 추가

## Use Case Diagram

```python
고객:
  1. 상품 조회 (검색)
  2. 장바구니 추가 → 수량 변경 → 제거
  3. 주문 생성 (장바구니 → 주문)
  4. 결제 처리
  5. 주문 조회 (이력)
  6. 환불 요청
     ├─ 전체 환불 (주문 전체)
     └─ 부분 환불 (특정 상품)
  7. 배송 조회

관리자:
  1. 상품 등록/수정
  2. 재고 관리
  3. 주문 처리 (상태 변경)
  4. 환불 승인/거절
```
