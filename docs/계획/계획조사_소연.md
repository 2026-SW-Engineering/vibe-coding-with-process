# 박소연

## 소프트웨어공학 프로세스

- 요구사항분석 → 설계 → 구현 → 테스트 → 유지보수

→ 프로세스의 각 단계별로 필요한 산출물을 적어보았음.

## 소공 프로세스 입각

### 1. 요구사항분석

- 요구사항명세서(SRS; Software Requirements Specification)
    - 기능 요구사항
    - 비기능 요구사항
- 유스케이스 다이어그램
- 유스케이스 명세서

llm에게 SRS 전체를 주고, “이 명세에 따라 구현해줘”

### 2. 설계

- 아키텍처 스타일 결정
- 클래스 다이어그램
- 시퀀스 다이어그램
- ERD
- API 명세 (?)
- 상태 다이어그램(주문 상태 전이)

### 3. 구현

코드는 LLM

### 4. 테스트

- 테스트케이스 명세
- 바이브코딩, 소공 프로세스 거친 sw를 모두 같은 테스트케이스로 테스트를 해야 결과를 비교할 수 있을 것 같음.
    - 근데, 교수님께서 바이브코딩 시 테스트 케이스 너가 만들어서 테스트해. 이런 것보다 직접 테스트케이스 만들라고 하신거 같은데, 이걸 실험해보는게 좋을지? → 의견이 궁금합니다.

### 5. 유지보수

- 변경사항을 주고, 어떻게 바꾸는지(싹다 갈아엎는다거나), 얼마나 토큰이 드는지

## 바이브코딩

- 입력: 쇼핑몰 주문 시스템 만들어줘. 장바구니, 주문, 결제, 환불 기능 포함
- 개발 방식: 실행해보고 안되면 LLM한테 다시 넣고 → 수정 반복
- 미리 명세나 설계를 작성하지 않기.

- 궁금한 점 ) [CLAUDE.md](http://CLAUDE.md) 작성 이런거 조차 설계로 보는거겠죠? 클로드md 잘 작성하고 한다는 것은 프로세스에 입각한 것인지가 궁금해서…

그래서 소공 프로세스 입각 sw 결과 와 바이브코딩sw 결과 를 같은 테스트 케이스로 테스트 해봤을 때 결과를 비교해보기
