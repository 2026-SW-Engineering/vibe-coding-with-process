# 요구사항 분석_김태건

## 요구사항 분석

- 주문 시스템
    - 고객이 상품을 검색 → 장바구니 → 주문 → 결제 → 환불
- Actor
    - Customer: 상품 검색, 장바구니 담기, 주문, 환불
    - Admin: 상품 등록, 재고 관리, 주문 처리
    - System: 결제 처리, 재고 차감, 상태 관리
- 기능 요구사항
    - 상품 관리
        - 상품 조회
        - 상품 등록/수정
        - 상품 재고 조회
    - 장바구니
        - 장바구니 상품 추가
        - 장바구니 상품 수량 변경
        - 장바구니 상품 제거
        - 장바구니 조회(목록&총액)
    - 주문
        - 주문 생성(장바구니 → 주문 전환)
        - 주문 조회(자신의 주문 이력)
        - 주문 상태 관리(대기 → 처리중 → 완료)
        - 주문 취소(특정 상태에서만 가능)
    - 결제 & 환불
        - 결제 처리(가격 확정 & 결제)
        - 전체 환불(주문 전체 취소)
        - 부분 환불(일부 상품 환불)
        - 환불 이력 조회
- 고려해야할 점
    - 재고 동시성 문제
    - 가격 변동 문제
    - 부분 환불 문제
    - 배송 상태에 따른 환불 불가 처리
    - 결제 실패 처리
    - 동일 상품 중복 장바구니 추가

- 다이어그램 계획
    1. 유스케이스 다이어그램 → just 시각화 목적(무엇을 할 수 있는지 보여주는 게 다이기 때문)
    2. 유스케이스 명세서
        - 유스케이스 명세서 포맷(md파일)
            
            ```markdown
            ## UC-01: 주문 생성
            
            ### Normal Flow
            1. 고객이 장바구니 상품 확인
            2. 배송 주소 입력
            3. 주문 버튼 클릭
            4. 시스템: 재고 확인 [EC-01] ← 여기가 중요!
            5. 시스템: order INSERT + order_item INSERT + stock UPDATE (Atomic)
            6. 장바구니 비우기
            7. 주문 완료 페이지 표시
            
            ### Exception Flow
            - E1 (재고 부족): "재고가 부족합니다" 에러 반환 후 주문 취소
            - E2 (배송 주소 누락): 입력 검증 실패
            - E3 (결제 실패): [EC-13, EC-14] 참조
            ```
            
        - 이후 이를 활용한 프롬프트
            
            ```python
            # Phase 1 구현 시 프롬프트
            prompt = f"""
            위 {유스케이스_명세서}에 따라 Python 함수를 구현해줘.
            특히 다음을 유의:
            - Normal Flow의 각 단계 구현
            - Exception Flow E1, E2, E3 처리
            - 재고 차감 시 SELECT FOR UPDATE 사용 [EC-01]
            """
            ```
