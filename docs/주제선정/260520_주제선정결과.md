## 0. Vibe Coding vs. 전통 SW 공학 프로세스

### 바이브코딩이란?

바이브코딩은 2025년 안드레 카파시가 사용한 표현으로, 사람이 만들고 싶은 서비스의 의도와 느낌을 자연어로 설명하면 LLM 기반 AI가 코드를 생성하고, 사람은 **코드 자체보다 실행 결과**를 보며 프롬프트로 수정해가는 개발 방식이다. 다음과 같은 특징이 있다.

- 자연어 프롬프트 중심으로 개발 진행
- 개발자는 코드 자체보다 실행 결과와 사용자 경험을 중심을 판단
- 오류가 발생하면 코드 직접 디버깅(X), 에러 메시지를 다시 LLM에게 전달하여 수정하도록(O)
- 전통적인 명세, 설계, 코드리뷰, 테스트 절차보다는 빠른 구현과 반복 수정에 초점을 둔다.

### 전통 SW 공학 프로세스란?

전통적인 소프트웨어 공학 프로세스는 SW를 체계적으로 개발하기 위해 다음과 같은 단계를 거친다.

> 요구사항 분석 → 설계 → 구현 → 테스트 → 배포 및 유지보수
> 

### 과제에서 우리의 접근 방식

- 구현 단계에서는 LLM을 사용할 수 있다. 하지만 개발 전후로 요구사항 정의, 설계, 테스트, 검증, 유지보수 전략을 포함하고자 한다. LLM을 구현 도구로 활용하되, 그 앞뒤에 공학적 절차를 배치한다.
- 그리고 이러한 “SW 공학 프로세스를 지켰을 때”와 “only 바이브코딩으로 했을 때”의 차이를 비교한다.

## 1. 주제 선정 기준

특정 SW를 잘 만드는 것이 아니라, **바이브코딩 방식 개발과 SW 공학 프로세스 적용했을 때 차이를 비교**하고, 그 과정에서 얻은 교훈을 분석하는 것이다.

따라서, SW 구현 난이도 자체보다, 요구사항 분석, 설계, 테스트, 품질 관리의 필요성이 잘 드러나는 방향으로 선정하고자 한다.

1. 요구사항이 겉보기에는 단순하다.
    - “만들어줘” 요청했을 때, 그럴 듯하게 만들어주지만, 실제로 써보면 예외 상황, 사용자 흐름, 오류 처리 등 요구사항 분석이 필요함을 느낄 수 있는 주제
2. 구현 난이도를 낮춘다.
    - SW 제품보다는 개발 프로세스 적용 여부에 따른 차이를 분석하는 것이기 때문이다.

## 2. 주제

주제: **쇼핑몰 주문 시스템**

- 바이브코딩을 하면 망가질 것 같은 요소가 있다.
    - 장바구니 담은 후 가격이 바뀌는 것을 처리?
    - 재고가 1개 남았는데, 두 사람 동시 결제하면 어떻게 처리?
    - 부분 환불이 가능한가?
    - 이러한 것들은 명세 없이 만들어줘. 했을 때 깨질 것 같은데, 실제로 그럴지 궁금하다.

프로세스 있는 개발 vs. 없는 바이브 코딩의 효과를 어떻게, 어떤 관점에서 비교할 수 있을지

예시)

- 프로세스 없이도 잘 되더라
- 프로세스를 따랐더니 토큰이 절약되더라
- 요구사항을 사람이 직접 뽑기 vs. “너가 요구사항 뽑아봐” 의 차이 보기
- 설계 단계에서 다이어그램 없으면, 모듈 경계가 흐려지는지?
- 설계가 없으면 수정 비용이 커지는지? 얼마나 커지는지? 토큰 비용?
- 얼만큼 자세하게 분석, 설계를 해주는 것이 좋은지?
