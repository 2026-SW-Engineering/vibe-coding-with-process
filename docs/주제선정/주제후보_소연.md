- 바이브코딩: 사람이 원하는 서비스의 느낌/분위기(vibe)와 의도를 자연어로 표현하면, AI가 이를 바탕으로 코드를 생성하는 소프트웨어 개발 방식이다. 명세, 설계, 테스트 같은 공학 단계를 건너뛴다.
    - 코드를 읽지 않고, 결과물의 동작만 보고 판단하며,
    - 틀리면 그대로 LLM한테 던져서 고쳐달라고 하는 것. (사람이 디버깅 안함)
- 전통 SW 공학 프로세스: 요구사항 분석 → 설계 → 구현 → 테스트 → 유지보수.
    - 우리의 경우, 구현에 LLM을 사용하는 것은 동일하지만, **앞 뒤로 공학적 절차를 두는지 안두는지**가 바이브코딩과 차이로 보면 될 것 같다.

## 주제 선정 기준

바이브코딩 vs. 전통 SW 공학 프로세스의 차이를 잘 드러내야 한다.

1. 요구사항이 겉보기에는 단순하지만, 숨은 복잡성이 있어야 한다.
    - 그냥 만들어줘. 하면 그럴 듯하게 만들어주지만, 막상 써보면 요구사항 분석이 필요함을 느낄 수 있는 주제
2. 구현 난이도는 낮게 잡는다.
    - 프로세스가 주제이지, sw 제품이 주제가 아니므로.

## 실험할 수 있는 포인트

- 요구사항을 사람이 직접 뽑은 후, 그거 바탕으로 llm한테 코딩 시키기 vs. 자연어로 먼저 만들어줘. 한다음에 너가 요구사항 뽑아봐. 했을 때 차이
- 설계 단계에서 다이어그램이 없으면, 모듈 경계가 흐려질 수 있다 → 나중에 수정 비용이 커진다.
- 전체 코드를 매번 다시 만들게 하는 비용 vs. 명세 정리 후 부분 수정하는 비용을 비교
